# RenderQueueManagerJsonExtensions

> **Status: source file removed.** `Utilities/RenderQueueManagerJsonExtensions.cs` was deleted from the repository in commit `ee7b83f` ("fix: remove junk JsonExtensions files generated by engines"). It is not part of the current source tree or the build. This document describes its last committed version (`ee7b83f^`) and is kept for reference only.

Provides `System.Text.Json` serialization helpers for `RenderQueueManager` in the `SkiaSharpChartEngine.Utilities` namespace. The extensions convert a `RenderQueueManager` instance to a JSON string and read one back.

The helpers are of little practical use. `RenderQueueManager` has no public properties. Its state is held in private fields (the job queue, a lock object, the active render count, and the `ILogger`), and its public members are methods. The JSON form is therefore always an empty object, and no queue state is written out. Deserialization also cannot rebuild a working manager, because the class has no parameterless constructor (see [Notes](#notes)).

For the manager itself, see [RenderQueueManager](RenderQueueManager.md).

## Build status when the file existed

The file was compiled into the library. The project file in that era did not exclude `Utilities/`, and the extensions lived in the same `SkiaSharpChartEngine.Utilities` namespace as `RenderQueueManager`, so no `using` directive was needed.

## Configuration

The extensions share a single private `JsonSerializerOptions` instance with these settings:

- `PropertyNamingPolicy` set to `JsonNamingPolicy.CamelCase`.
- `WriteIndented` set to `false`.
- `PropertyNameCaseInsensitive` set to `true`.
- `TypeInfoResolver` set to `new DefaultJsonTypeInfoResolver()`, which is the reflection-based resolver. The helpers are therefore not compatible with trimmed or AOT-published output without a source-generated context.

No `ReferenceHandler` is set. A cyclic object graph would fail to serialize, but `RenderQueueManager` exposes no object graph, so this does not occur in practice.

## API

### `public static string ToJson`

Serializes a `RenderQueueManager` instance to a JSON string. When `indented` is `true`, it serializes with a copy of the shared options with `WriteIndented` set to `true`. Otherwise it uses the shared options directly.

**Parameters**
- `value` (`RenderQueueManager`, `this`): The instance to serialize.
- `indented` (`bool`, optional): Whether to format the JSON with indentation (default: `false`).

**Return Value**
- `string`: The JSON representation. Because the class has no public properties, this is always `{}`.

**Exceptions**
- `ArgumentNullException`: Thrown when `value` is `null`.
- `JsonException`: Documented in the source XML comments as thrown when serialization fails. No failure case was identified for this class, since it has no public members to serialize.

---

### `public static RenderQueueManager? FromJson`

Deserializes a JSON string to a `RenderQueueManager` instance.

**Parameters**
- `json` (`string`): The JSON string to deserialize.

**Return Value**
- `RenderQueueManager?`: The deserialized instance, or `null` when `System.Text.Json` throws `JsonException`. A literal `null` JSON token also yields `null`. In practice, deserialization does not produce a usable instance (see [Notes](#notes)).

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `ArgumentException`: Thrown when `json` is an empty string. The check is applied to the raw input, so whitespace-only input is not rejected here and reaches `System.Text.Json`.
- `InvalidOperationException`: Thrown by `System.Text.Json` for a type with no usable constructor. This happens before the JSON is read, so it occurs even for malformed input. It is not a `JsonException`, so it is not caught and propagates to the caller.

The XML comment on this method describes the `ArgumentException` case as "null or empty". For `null` input, the `ArgumentException.ThrowIfNullOrEmpty` guard throws `ArgumentNullException`, not `ArgumentException`.

---

### `public static bool TryFromJson`

Attempts to deserialize a JSON string to a `RenderQueueManager` instance. Catches `JsonException` and reports failure through the return value.

**Parameters**
- `json` (`string`): The JSON string to deserialize.
- `value` (`RenderQueueManager?`, `out`): Receives the deserialized instance. It is `null` when the method returns `false`.

**Return Value**
- `bool`: `true` when `System.Text.Json` returns without throwing, including when the result is `null`; otherwise, `false`. Unlike `FromJson`, a `true` result does not guarantee a non-null `value`.

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `ArgumentException`: Thrown when `json` is an empty string.
- `InvalidOperationException`: Propagates from `System.Text.Json` for the same reason as `FromJson`. It is not caught.

---

## Usage

```csharp
using SkiaSharpChartEngine.Utilities;

RenderQueueManager manager = /* resolved from DI or created with an ILogger<RenderQueueManager> */;

string compact = manager.ToJson();
string indented = manager.ToJson(indented: true);

RenderQueueManager? restored = RenderQueueManagerJsonExtensions.FromJson(compact);

if (RenderQueueManagerJsonExtensions.TryFromJson(indented, out var parsed))
{
    // parsed may still be null if the JSON was the literal null
}
```

## Notes

- `ToJson` is the only extension method on the instance. `FromJson` and `TryFromJson` are declared in a `static` class, so call them as `RenderQueueManagerJsonExtensions.FromJson(...)`.
- `RenderQueueManager` has a single constructor, which takes `ILogger<RenderQueueManager>` and an optional `maxConcurrentRenders`, and no parameterless constructor. `System.Text.Json` cannot bind the logger to a JSON property, so deserialization is not expected to succeed. The behavior was checked with a scratch program: a type with only a single-argument constructor and no parameterless constructor made `JsonSerializer.Deserialize` throw `InvalidOperationException` for both `{}` and malformed input.
- Because no state is serialized, a round trip cannot restore queued jobs, the active render count, or the concurrency limit. The queue would be empty and the limit would be the default of `4` if a manager could be constructed.
- The `RenderQueueManager` page describes an older API (for example, `Enqueue(RenderJob)` and a parameterless constructor). The signatures in the source at `ee7b83f^` are `Enqueue(Chart chart, int priority = 0)` and a constructor that requires `ILogger<RenderQueueManager>`. This page follows the source.
