# ChartInteractionServiceJsonExtensions

> **Status: source file removed.** `Services/ChartInteractionServiceJsonExtensions.cs` was deleted from the repository in commit `ee7b83f` ("fix: remove junk JsonExtensions files generated by engines"). It is not part of the current source tree or the build. This document describes its last committed version (`ee7b83f^`) and is kept for reference only.

Provides `System.Text.Json` serialization helpers for `ChartInteractionService` in the `SkiaSharpChartEngine.Services` namespace. The extensions convert a `ChartInteractionService` instance to a JSON string and read one back, using camelCase property names.

The helpers are of little practical use. `ChartInteractionService` keeps its state in private fields (the selection map, a lock object, an `IInteractivityService`, and an `ILogger`). It exposes no public properties, and its public members are events and methods. The JSON form is therefore always an empty object, and the selection state is never written out. Deserialization also cannot rebuild a working service, because the class has no parameterless constructor (see [Notes](#notes)).

For the service itself, see [ChartInteractionService](ChartInteractionService.md). For the interface it implements, see [IChartInteractionService](IChartInteractionService.md).

## Build status when the file existed

The file was compiled into the library. The project file in that era did not exclude `Services/`, and the extensions lived in the same `SkiaSharpChartEngine.Services` namespace as `ChartInteractionService`, so no `using` directive was needed.

## Configuration

The extensions share a single private `JsonSerializerOptions` instance built from `JsonSerializerDefaults.Web`, with these overrides:

- `PropertyNamingPolicy` set to `JsonNamingPolicy.CamelCase`.
- `WriteIndented` set to `false`.
- `ReferenceHandler` set to `ReferenceHandler.IgnoreCycles`.

No `TypeInfoResolver` is set, so the default reflection-based resolver is used. The helpers are therefore not compatible with trimmed or AOT-published output without a source-generated context.

## API

### `public static string ToJson`

Serializes a `ChartInteractionService` instance to a JSON string. When `indented` is `true`, it serializes with a new copy of the shared options with `WriteIndented` set to `true`. Otherwise it uses the shared options directly.

**Parameters**
- `value` (`ChartInteractionService`, `this`): The instance to serialize.
- `indented` (`bool`, optional): Whether to format the JSON with indentation (default: `false`).

**Return Value**
- `string`: The JSON representation. Because the class has no public properties and events are not serialized, this is always `{}`.

**Exceptions**
- `ArgumentNullException`: Thrown when `value` is `null`.

---

### `public static ChartInteractionService? FromJson`

Deserializes a JSON string to a `ChartInteractionService` instance.

**Parameters**
- `json` (`string`): The JSON string to deserialize.

**Return Value**
- `ChartInteractionService?`: The deserialized instance, or `null` when `System.Text.Json` throws `JsonException`. In practice, deserialization does not produce a usable instance (see [Notes](#notes)).

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `ArgumentException`: Thrown when `json` is empty or whitespace only. The check is applied to `json.Trim()`.
- `InvalidOperationException`: Thrown by `System.Text.Json` for a type with no usable constructor. Only `JsonException` is caught, so this exception propagates to the caller.

---

### `public static bool TryFromJson`

Attempts to deserialize a JSON string to a `ChartInteractionService` instance. Catches `JsonException` and reports failure through the return value.

**Parameters**
- `json` (`string`): The JSON string to deserialize.
- `value` (`ChartInteractionService?`, `out`): Receives the deserialized instance. It is `null` when the method returns `false`. The parameter is annotated with `[NotNullWhen(true)]`.

**Return Value**
- `bool`: `true` if deserialization produced a non-null instance; otherwise, `false`.

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `ArgumentException`: Thrown when `json` is empty or whitespace only.
- `InvalidOperationException`: Propagates from `System.Text.Json` for the same reason as `FromJson`. It is not caught.

---

## Usage

```csharp
using SkiaSharpChartEngine.Services;

ChartInteractionService service = /* resolved from DI or created with its dependencies */;

string compact = service.ToJson();
string indented = service.ToJson(indented: true);

ChartInteractionService? restored = ChartInteractionServiceJsonExtensions.FromJson(compact);

if (ChartInteractionServiceJsonExtensions.TryFromJson(indented, out var parsed))
{
    // parsed is the deserialized instance
}
```

## Notes

- `ToJson` and `FromJson` are the only public entry points besides `TryFromJson`. They are declared in a `static` class, so call them as `ChartInteractionServiceJsonExtensions.FromJson(...)`. Only `ToJson` is an extension method on the instance.
- The guard for empty input is `ArgumentException.ThrowIfNullOrEmpty(json.Trim())`. Whitespace-only input is therefore rejected with `ArgumentException`, unlike the `MetricsCollector` helpers, where whitespace reaches `JsonSerializer` and raises `JsonException`.
- `ChartInteractionService` has a single constructor, which takes `IInteractivityService` and `ILogger<ChartInteractionService>`, and no parameterless constructor. `System.Text.Json` cannot bind either parameter to a JSON property, so deserialization is not expected to succeed. The original XML comments on `FromJson` and `TryFromJson` state that the method "returns null if deserialization fails" and that the class has "constructor dependencies that prevent proper deserialization". Only the `JsonException` case is covered by that wording. The `InvalidOperationException` path is not covered and is not caught. This was determined by reading the type, not by running a round-trip test.
- Events (`Clicked`, `Hovered`, `SelectionChanged`) and the selection dictionary are not serialized, so no interaction or selection state survives a round trip.
