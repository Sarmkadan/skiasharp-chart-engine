# ConfigurationServiceJsonExtensions

> **Status: source file removed.** `Services/ConfigurationServiceJsonExtensions.cs` was deleted from the repository in commit `ee7b83f` ("fix: remove junk JsonExtensions files generated by engines"). It is not part of the current source tree or the build. This document describes its last committed version (`ee7b83f^`) and is kept for reference only.

Provides `System.Text.Json` serialization helpers for `ConfigurationService` in the `SkiaSharpChartEngine.Services` namespace. The extensions convert a `ConfigurationService` instance to a JSON string and read one back, using camelCase property names.

The helpers are of little practical use. `ConfigurationService` keeps its state in private fields (the configuration dictionary, and an `ILogger<ConfigurationService>`). It exposes no public properties, and its public members are methods. The JSON form is therefore always an empty object, and the stored configurations are never written out. Deserialization also cannot rebuild a working service, because the class has no parameterless constructor (see [Notes](#notes)).

For the service itself, see [ConfigurationService](ConfigurationService.md). For the chart configuration type it stores, see [ChartConfiguration](ChartConfiguration.md).

## Build status when the file existed

The file was compiled into the library. The project file in that era did not exclude `Services/ConfigurationService.cs`, and the extensions lived in the same `SkiaSharpChartEngine.Services` namespace as `ConfigurationService`, so no `using` directive was needed.

## Configuration

The extensions share a single private `JsonSerializerOptions` instance built from `JsonSerializerDefaults.Web`, with these overrides:

- `PropertyNamingPolicy` set to `JsonNamingPolicy.CamelCase`.
- `WriteIndented` set to `false`.
- `DefaultIgnoreCondition` set to `JsonIgnoreCondition.WhenWritingNull`.
- `ReferenceHandler` set to `ReferenceHandler.IgnoreCycles`.

No `TypeInfoResolver` is set, so the default reflection-based resolver is used. The helpers are therefore not compatible with trimmed or AOT-published output without a source-generated context.

## API

### `public static string ToJson` (extension method)

Serializes a `ConfigurationService` instance to a JSON string. When `indented` is `true`, it serializes with a new copy of the shared options with `WriteIndented` set to `true`. Otherwise it uses the shared options directly.

**Parameters**
- `value` (`ConfigurationService`, `this`): The instance to serialize.
- `indented` (`bool`, optional): Whether to format the JSON with indentation (default: `false`).

**Return Value**
- `string`: The JSON representation. Because the class has no public properties, this is always `{}`, with or without indentation.

**Exceptions**
- `ArgumentNullException`: Thrown when `value` is `null`.

---

### `public static ConfigurationService? FromJson`

Deserializes a JSON string to a `ConfigurationService` instance.

**Parameters**
- `json` (`string`): The JSON string to deserialize.

**Return Value**
- `ConfigurationService?`: `null` when `json` is an empty string. Otherwise the deserialized instance. In practice, deserialization does not produce a usable instance (see [Notes](#notes)).

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `JsonException`: Thrown when `System.Text.Json` rejects malformed JSON. The original exception is wrapped with the message `Failed to deserialize ConfigurationService from JSON`.
- `InvalidOperationException`: Thrown by `System.Text.Json` for valid JSON, because the type has no usable constructor. This exception is not caught and propagates to the caller.

---

### `public static bool TryFromJson`

Attempts to deserialize a JSON string to a `ConfigurationService` instance. Catches `JsonException` and reports failure through the return value.

**Parameters**
- `json` (`string`): The JSON string to deserialize.
- `value` (`ConfigurationService?`, `out`): Receives the deserialized instance. It is `null` when the method returns `false`, and also when `json` is empty.

**Return Value**
- `bool`: `true` if deserialization completed without a `JsonException`; otherwise, `false`. Because `System.Text.Json` cannot build the type, a `true` result with a usable instance does not occur in practice.

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `InvalidOperationException`: Propagates from `System.Text.Json` for valid JSON, for the same reason as `FromJson`. It is not caught.

---

## Usage

```csharp
using SkiaSharpChartEngine.Services;

ConfigurationService service = /* resolved from DI or created with an ILogger<ConfigurationService> */;

string compact = service.ToJson();
string indented = service.ToJson(indented: true);

ConfigurationService? restored = ConfigurationServiceJsonExtensions.FromJson(compact);

if (ConfigurationServiceJsonExtensions.TryFromJson(indented, out var parsed))
{
    // parsed is the deserialized instance
}
```

## Notes

- `ToJson` is the only extension method. `FromJson` and `TryFromJson` are static methods on a `static` class, so call them as `ConfigurationServiceJsonExtensions.FromJson(...)` and `ConfigurationServiceJsonExtensions.TryFromJson(...)`.
- Empty input and whitespace-only input are handled differently. An empty string makes `FromJson` return `null` and `TryFromJson` return `false` without calling `System.Text.Json`. Whitespace-only input goes to `System.Text.Json`, which rejects it with `JsonException`, so `FromJson` throws and `TryFromJson` returns `false`.
- `ConfigurationService` has a single constructor, which takes `ILogger<ConfigurationService>`, and no parameterless constructor. `System.Text.Json` cannot bind the logger parameter to a JSON property, so deserialization of valid JSON fails with `InvalidOperationException`. The `FromJson` XML comment says it returns `null` when "deserialization fails", but that applies only to the `JsonException` path. The `InvalidOperationException` path is not covered and is not caught.
- The `InvalidOperationException` behavior was confirmed by running the last committed version of the file (`ee7b83f^`) in a scratch console project against a stub `ConfigurationService` with the same constructor shape. The stub kept the private fields and the `ILogger<ConfigurationService>` parameter, and the test used no real logger. Results: `ToJson` returned `{}` in both modes; `FromJson("{}")` and `TryFromJson("{}")` threw `InvalidOperationException`; `FromJson("not json")` threw the wrapped `JsonException`; `TryFromJson("not json")` returned `false`; `FromJson("")` returned `null`.
- The stored configurations (the private `Dictionary<string, ChartConfiguration>`) are not serialized, so no configuration state survives a round trip.
