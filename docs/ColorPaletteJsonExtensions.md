# ColorPaletteJsonExtensions

> **Status: source file removed.** `Models/ColorPaletteJsonExtensions.cs` was deleted from the repository in commit `ee7b83f` ("fix: remove junk JsonExtensions files generated by engines"). It is not part of the current source tree or the build. This document describes its last committed version (`ee7b83f^`) and is kept for reference only.

Provides `System.Text.Json` serialization helpers for `ColorPalette` in the `SkiaSharpChartEngine.Models` namespace. The extensions convert a `ColorPalette` to a JSON string and attempt to read one back, using camelCase property names.

## Configuration

The extensions share a single private `JsonSerializerOptions` instance, created from `JsonSerializerDefaults.Web` with:

- `WriteIndented` set to `false`.
- `PropertyNamingPolicy` set to `JsonNamingPolicy.CamelCase`.
- `DefaultIgnoreCondition` set to `JsonIgnoreCondition.WhenWritingNull`.

No enum converter is configured. `ColorPalette` has no enum members.

## API

### `public static string ToJson`

Serializes a `ColorPalette` instance to a JSON string. When `indented` is `true`, the method serializes with a copy of the shared options that has `WriteIndented` enabled. Otherwise it uses the shared options directly.

**Parameters**
- `value` (`ColorPalette`, `this`): The palette to serialize.
- `indented` (`bool`, optional): Whether to format the JSON with indentation (default: `false`).

**Return Value**
- `string`: The JSON representation of the palette, with `name` and `colors` properties.

**Exceptions**
- `ArgumentNullException`: Thrown when `value` is `null`.

---

### `public static ColorPalette? FromJson`

Deserializes a JSON string to a `ColorPalette` instance.

**Parameters**
- `json` (`string`): The JSON string to deserialize.

**Return Value**
- `ColorPalette?`: The deserialized instance, or `null` if `json` is `null` or empty.

**Exceptions**
- `NotSupportedException`: Thrown for any non-empty input. See the Notes section.
- `JsonException`: Documented in the original XML comment, but not reached in practice. See the Notes section.

---

### `public static bool TryFromJson`

Attempts to deserialize a JSON string to a `ColorPalette` instance. The method is documented to catch `JsonException` and report failure through the return value.

**Parameters**
- `json` (`string`): The JSON string to deserialize.
- `value` (`ColorPalette?`, `out`): Receives the deserialized instance, or `null` on failure.

**Return Value**
- `bool`: `true` if deserialization succeeds; otherwise, `false`.

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.

---

## Usage

```csharp
using SkiaSharpChartEngine.Models;

ColorPalette palette = ColorPalette.CreateDefaultPalette();

string compact = palette.ToJson();
string indented = palette.ToJson(indented: true);
// compact: {"name":"Default","colors":["#1f77b4","#ff7f0e",...]}

// Not safe with the current ColorPalette type; see Notes.
ColorPalette? restored = ColorPaletteJsonExtensions.FromJson(compact);
```

## Notes

- **Deserialization does not work.** `ColorPalette` has no parameterless constructor and has two public parameterized constructors (`(string name)` and `(string name, IEnumerable<string> colors)`). `System.Text.Json` only uses a constructor when there is exactly one public parameterized constructor, or when one is annotated with `[JsonConstructor]`. Neither holds here. This was verified by compiling the last committed `ColorPalette.cs` and `ColorPaletteJsonExtensions.cs` in a scratch project outside the repository: `FromJson` threw `NotSupportedException` for a valid round-trip payload.
- **`TryFromJson` does not catch the failure.** Its `catch` only handles `JsonException`, and the exception above is `NotSupportedException`. The probe confirmed that `TryFromJson` throws for both valid and malformed input, so it does not return `false` as documented.
- **Serialization works.** `ToJson` produced `{"name":"Default","colors":[...]}` for `CreateDefaultPalette()`, and the indented form was multi-line as expected.
- **`Colors` is read-only.** It has a getter but no setter, so even a working deserializer could not populate it through the property. The palette's color list is only filled through the constructors or `AddColor`.
- If these helpers are revived, `ColorPalette` needs a `[JsonConstructor]`-annotated constructor (taking `name` and `colors`) for deserialization to work, and `TryFromJson` should catch `NotSupportedException` as well as `JsonException`. Either change alters existing behavior, so it should be a separate change.
