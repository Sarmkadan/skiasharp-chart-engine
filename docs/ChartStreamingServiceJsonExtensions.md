# ChartStreamingServiceJsonExtensions

> **Status: source file removed.** `Streaming/ChartStreamingServiceJsonExtensions.cs` was deleted from the repository in commit `ee7b83f` ("fix: remove junk JsonExtensions files generated by engines"). It is not part of the current source tree or the build. This document describes its last committed version (`ee7b83f^`) and is kept for reference only.

Provides `System.Text.Json` serialization helpers for `ChartStreamingService` in the `SkiaSharpChartEngine.Streaming` namespace. The extensions convert a `ChartStreamingService` instance to a JSON string and read one back, using camelCase property names.

The helpers are of little practical use. `ChartStreamingService` keeps all of its state in private fields (the stream registry, the rendering service, a logger, and a disposed flag). It exposes no public properties, and its public members are methods. The JSON form is therefore always an empty object, and no registered streams or buffered points are written out. Deserialization also cannot rebuild a working service, because the class has no parameterless constructor (see [Notes](#notes)).

For the service itself, see [ChartStreamingService](ChartStreamingService.md). For the interface it implements, see [IChartStreamingService](IChartStreamingService.md).

## Build status when the file existed

The file was compiled into the library. The project file does not exclude `Streaming/`, and the extensions lived in the same `SkiaSharpChartEngine.Streaming` namespace as `ChartStreamingService`, so no `using` directive was needed.

## Configuration

The extensions share a single private `JsonSerializerOptions` instance built from `JsonSerializerDefaults.Web`, with these overrides:

- `PropertyNamingPolicy` set to `JsonNamingPolicy.CamelCase`.
- `WriteIndented` set to `false`.
- `TypeInfoResolver` set to `new DefaultJsonTypeInfoResolver()`.

Unlike the sibling `ChartInteractionServiceJsonExtensions`, no `ReferenceHandler` is set. `DefaultJsonTypeInfoResolver` uses reflection, so the helpers are not compatible with trimmed or AOT-published output without a source-generated context.

## API

### `public static string ToJson` (extension method)

Serializes a `ChartStreamingService` instance to a JSON string. When `indented` is `true`, it serializes with a new copy of the shared options with `WriteIndented` set to `true`. Otherwise it uses the shared options directly.

**Parameters**
- `value` (`ChartStreamingService`, `this`): The instance to serialize.
- `indented` (`bool`, optional): Whether to format the JSON with indentation (default: `false`).

**Return Value**
- `string`: The JSON representation. Because the class has no public properties, this is always `{}`.

**Exceptions**
- `ArgumentNullException`: Thrown when `value` is `null`.

---

### `public static ChartStreamingService? FromJson`

Deserializes a JSON string to a `ChartStreamingService` instance.

**Parameters**
- `json` (`string`): The JSON string to deserialize.

**Return Value**
- `ChartStreamingService?`: The deserialized instance, or `null` when the input is empty, or when `System.Text.Json` throws `JsonException` (malformed JSON, or whitespace-only input). In practice, valid JSON does not produce a usable instance (see [Notes](#notes)).

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `InvalidOperationException`: Thrown by `System.Text.Json` for a type with no usable constructor, such as valid JSON input like `{}`. Only `JsonException` is caught, so this exception propagates to the caller.

---

### `public static bool TryFromJson`

Attempts to deserialize a JSON string to a `ChartStreamingService` instance. Catches `JsonException` and reports failure through the return value.

**Parameters**
- `json` (`string`): The JSON string to deserialize.
- `value` (`ChartStreamingService?`, `out`): Receives the deserialized instance. It is `null` when the method returns `false`.

**Return Value**
- `bool`: `true` if deserialization produced a non-null instance; otherwise, `false`.

**Exceptions**
- `ArgumentNullException`: Thrown when `json` is `null`.
- `InvalidOperationException`: Propagates from `System.Text.Json` for the same reason as `FromJson`. It is not caught.

---

## Usage

```csharp
using SkiaSharpChartEngine.Streaming;

ChartStreamingService service = /* resolved from DI or created with its dependencies */;

string compact = service.ToJson();
string indented = service.ToJson(indented: true);

ChartStreamingService? restored = ChartStreamingServiceJsonExtensions.FromJson(compact);

if (ChartStreamingServiceJsonExtensions.TryFromJson(indented, out var parsed))
{
    // parsed is the deserialized instance
}
```

## Notes

- `ToJson` is an extension method on the instance. `FromJson` and `TryFromJson` are static methods of the `static` class, so call them as `ChartStreamingServiceJsonExtensions.FromJson(...)`.
- Empty input is handled differently by `FromJson` and `TryFromJson` than by the sibling helpers. An empty string returns `null` or `false`, and does not throw. The check is `string.IsNullOrEmpty(json)` on the raw string, so whitespace-only input is not caught by it. It reaches `JsonSerializer`, raises `JsonException`, and is caught there, which also yields `null` or `false`.
- `ChartStreamingService` has a single constructor, which takes `IChartRenderingService` and `ILogger<ChartStreamingService>`, and no parameterless constructor. `System.Text.Json` cannot bind these parameters to JSON properties, so valid JSON such as `{}` throws `InvalidOperationException`, not `JsonException`. The XML comments say the method "returns null if the JSON is invalid", which covers only the `JsonException` path. This was checked with a standalone type that has the same constructor shape (a `object` and an `int` parameter and no parameterless constructor), not with `ChartStreamingService` itself.
- The registry of streams (`_entries`), the buffered points, and the `IDisposable` state are private, so no streaming state survives a round trip. Calling `ToJson` does not dispose the service.
